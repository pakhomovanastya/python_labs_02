# Лабораторная работа №4: Интерфейсы и абстрактные классы (ABC)

*Абстрактный класс* – это класс, который не предназначен для создания экземпляров. Он служит шаблоном для других классов. Абстрактный класс может содержать абстрактные методы – методы, объявленные, но не реализованные. Любой класс, наследующий абстрактный класс, обязан реализовать все его абстрактные методы, иначе он тоже останется абстрактным (это класс, который определяет интерфейс, но не предоставляет полной реализации. Он может содержать абстрактные методы, которые должны быть реализованы в подклассах.).                 

В Python абстрактные классы создаются с помощью модуля abc:

- ABC – базовый класс для создания абстрактных классов.

- @abstractmethod – декоратор, помечающий метод как абстрактный.

*Интерфейс* – это абстрактный класс, содержащий только абстрактные методы (без реализации). Интерфейс задаёт контракт: класс, реализующий интерфейс, обязуется предоставить все его методы. Это позволяет различным классам иметь единое поведение.

### Полиморфизм через интерфейсы
*Полиморфизм* – способность объектов разных классов отвечать на один и тот же вызов метода по-разному. При использовании интерфейсов полиморфизм достигается естественно: программа работает с объектами через общий интерфейс, не заботясь об их конкретном типе.                

### Цель работы:
Познакомиться с абстрактными базовыми классами (ABC), освоить понятие интерфейса как контракта поведения, научиться задавать обязательные методы и реализовывать полиморфизм через единый интерфейс.           

### Интерфейсы interfaces.py (ABC)
Интерфейс: PassableExam, абстрактный метод `pass_exam()` обязательно сдавать экзамены               

Интерфейс: Admissible, абстрактный метод `admiss_university()` обязательно проходить поступление                

Интерфейс: DefendableDissertation, абстрактный метод `defend_dissertation()` обязательно защищать диссертацию               

### Классы и реализация интерфейсов models.py
Базовый класс `Student`
- Реализует интерфейсы `PassableExam` и `Admissible`.
- Предоставляет общую реализацию `pass_exam()` (универсальный вывод) и базовую `admiss_university()` (переопределяется в потомках).

Класс `BachelorStudent`
- Наследует `Student`.
- Переопределяет `admiss_university()`:
  - Если начальный курс `curse_start` равен 1: сдаёт математику и физику.
  - Иначе – только математику.

Класс `MasterStudent`
- Переопределяет `admiss_university()` аналогично, но с другим набором предметов (математика, физика, информатика).

Класс `PhDStudent`
- Дополнительно реализует интерфейс DefendableDissertation.
- Переопределяет `pass_exam()` – сдаёт научную работу.
- Реализует `defend_dissertation()` – выводит информацию о защите.

### Коллекция и фильтрация по интерфейсу models.py
В `StudentCollection` добавлен метод `get_student_dissertation()`, который фильтрует коллекцию по интерфейсу `DefendableDissertation`. Это демонстрирует, как коллекция может работать с интерфейсами, а не с конкретными классами.

### Сценарий 1: Данные о студентах и методы интерфейсов
Объекты разных типов (бакалавр, магистр, аспирант) создаются корректно, имеют свои атрибуты, и интерфейсные методы (`admiss_university`, `pass_exam`) вызываются и работают по-разному.             

1. Создаются шесть объектов: два бакалавра, два магистра, два аспиранта (первые три – для первого сценария).
2. Выводятся их строковые представления (`__str__`), которые у каждого класса дополнены специфическими полями.
3. Для каждого объекта вызывается `admiss_university()`.
  - Бакалавр (student1): начальный курс 2 выводит "сдаём математику".
  - Магистр (student2): курс 1 выводит "сдаём математику, физику, информатику".
  - Аспирант (student3): публикаций 4 (>2) выводит "сдаём математику".
4. Вызывается `pass_exam()` для разных предметов. Для аспиранта `pass_exam` переопределён и выводит сообщение о научной работе.
  - У аспиранта (student3) вызывается `pass_exam("- математике")` – выводит `"Nilitin Oleg сдаёт научную работу по - математике"`.

Наблюдаемый полиморфизм: одна и та же команда `admiss_university()` приводит к разному поведению в зависимости от реального типа объекта.

### Сценарий 2: Полиморфизм через интерфейсы

1. Создаётся список `list_student = [student4, student5, student6]` (бакалавр, магистр, аспирант).
2. Вызывается функция `admiss_in_univercity(list_student)`. Внутри она проходит по каждому элементу и вызывает `admiss_university()`. Это демонстрирует единообразную обработку объектов разных классов через интерфейс `Admissible`.
- Выводятся сообщения о поступлении в соответствии с логикой каждого класса.
3. Вызывается `pass_math(student4)` и `pass_math(student5)` – функция проверяет, что объект реализует `PassableExam` (это так), и вызывает `pass_exam("математика")`. У бакалавра и магистра выводятся обычные сообщения об экзаменах.
4. Проверяется, что при попытке передать в `pass_math` число 5 возникает исключение `TypeError`, которое перехватывается и выводится сообщение.
5. Выполняется проверка `isinstance` для трёх интерфейсов:
  - `student4` (бакалавр): `isinstance(student4, PassableExam)` True.
  - `student5` (магистр): `isinstance(student5, Admissible)` True.
  - `student6` (аспирант): `isinstance(student6, DefendableDissertation)` True.
