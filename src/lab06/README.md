# Лабораторная работа №6: Generics и typing

### Цель работы
Освоить систему аннотаций типов в Python, научиться создавать обобщённые (generic) классы с помощью `TypeVar` и `Generic`, понять концепцию структурной типизации через `typing.Protocol`.

### Аннотации типов (Type Hints)
**Аннотации типов** — это синтаксис Python, позволяющий указывать ожидаемые типы переменных, параметров функций и возвращаемых значений.                
(Подсказки типов позволяют указать ожидаемые типы переменных, аргументов функций и возвращаемых значений)

### Generics и TypeVar
**Generic (обобщённое программирование)** — возможность создавать классы и функции, которые могут работать с разными типами данных, сохраняя при этом типобезопасность.                 
(поскольку информация о типах объектов, хранящихся в контейнерах, не может быть получена статически, абстрактные базовые классы были расширены для поддержки подписки, обозначающей ожидаемые типы элементов контейнера)            

> `TypeCollection[T]` Generic-коллекция с методами add, remove, find, filter, map

### TypeVar
**TypeVar (переменная типа)** используется для объявления параметров обобщённых типов.              
(переменные типов существуют в первую очередь для удобства статической проверки типов. Они служат параметрами для обобщенных типов, а также для обобщенных определений функций)

> Generic[T] в качестве базового класса определяет, что класс принимает один параметр типа T. Это также делает T допустимым типом в теле класса.

**Ограничение через bound** — указывает, что тип должен быть подклассом указанного класса.

### Protocol – структурная типизация
**Protocol** — это способ определения интерфейса (набора методов), которому должен соответствовать объект. Главное отличие от обычного наследования: класс не нужно явно наследовать от Protocol — достаточно иметь подходящие методы.              
(протоколы определяют методы, которые должны быть у объекта. Структурная типизация означает, что тип считается подтипом протокола, если он обладает всеми методами, определенными в протоколе)          

> ` Displayable(Protocol)` протокол: объект должен иметь метод display() -> str
>
> ` Scorable(Protocol)` протокол: объект должен иметь метод score() -> float

Ключевые преимущества Protocol:
1. Не требуется явное наследование — достаточно наличия методов
2. Поддержка duck typing на уровне статической проверки типов
3. Обратная совместимость — существующие классы могут соответствовать протоколам без изменений

### Сценарий 1: TypeCollection[Student] — типизированная коллекция
Цель: Показать создание generic-коллекции с конкретным типом Student, добавление объектов и их вывод.               

Демонстрирует:
- Аннотация типа `TypeCollection[Student]` гарантирует, что в коллекцию можно добавлять только объекты `Student` (или его наследников)
- Метод `get_all()` возвращает `list[Student]`
- Работа с коллекцией типобезопасна

### Сценарий 2: Методы find, filter, map
Цель: Продемонстрировать методы высшего порядка с правильными аннотациями типов.                

**Метод find** — поиск элемента                 
Демонстрирует:                  
- `find` принимает предикат (функция `Callable[[T], bool]`)
- Возвращает `Optional[T]` — либо элемент, либо `None`
- Корректная обработка случая, когда элемент не найден

**Метод filter** — фильтрация                   
Демонстрирует:              
- `filter` принимает предикат и возвращает `list[T]`
- Можно создавать разные критерии фильтрации

**Метод map** — преобразование типов                    
Демонстрирует:                  
- `map` принимает функцию `Callable[[T], R]`
- Результат — `list[R]`, где R может отличаться от T
- Тип результата меняется: `list[str]` и `list[float]` — наглядное доказательство необходимости второго TypeVar R

### Сценарий 3: Protocol Displayable — коллекция с методом display()
Цель: Показать работу структурной типизации — объекты разных классов (не наследующих протокол) попадают в коллекцию TypeCollection[D], где D ограничен протоколом Displayable.                  

Демонстрирует:                  
- Коллекция объявлена с типом TypeCollection[Displayable]
- В неё добавляются объекты разных классов — это работает, потому что у всех есть метод display()
- Ни один класс не наследуется от Displayable — это пример структурной, а не номинативной типизации
